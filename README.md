🌊 SafeSignal Thailand

🇹🇭 Real-time flood safety information for Thailand

SafeSignal Thailand is a fast, mobile-first emergency information website designed to help people in Thailand understand flooding situations, find trusted emergency information, prepare their homes, and know what to do during dangerous conditions.

⚠️ Important: SafeSignal is an information and preparedness tool. It does not replace instructions from Thai emergency authorities. Always follow official evacuation orders and emergency instructions.

⸻

🚨 What is SafeSignal Thailand?

During a flood, information can become confusing very quickly.

SafeSignal Thailand brings important information into one simple interface:

* 🌧️ Current weather and flood warnings
* 🚨 Immediate flood-safety instructions
* 📞 Emergency telephone numbers
* 📰 Current flood-related updates
* 🏠 Home flood-preparation guidance
* 🧰 Emergency supply checklist
* 📍 Evacuation and shelter information
* 🗺️ Flood-map infrastructure
* 🛡️ Government and official information sources
* ⏱️ Information timestamps
* 📱 Mobile-first emergency interface

The goal is simple:

Know what is happening. Know what to do. Know who to call.

🌊 Flood Safety

SafeSignal provides short, actionable instructions rather than overwhelming users with large amounts of information.

Examples include:

🚫 Avoid floodwater

Do not:

* Walk through unknown-depth floodwater
* Drive through flooded roads
* Enter areas with strong currents
* Approach damaged electrical infrastructure
* Enter restricted or evacuated areas

Floodwater can conceal hazards and may become dangerous very quickly.

🏠 Protect your home

When it is safe to do so:

* Move important belongings to higher locations
* Protect important documents
* Keep phones and power banks charged
* Keep emergency supplies accessible
* Keep exits accessible
* Monitor official warnings

Never put yourself at risk to protect property.

📰 Live Information

SafeSignal is designed to display current emergency information from trusted sources.

Each important update should contain:

* 🕐 Time
* 📍 Location
* 📰 Source
* 📝 What changed
* 🔗 Original source

For example:

14:32
Bangkok Metropolitan Administration
Flood warning updated for affected districts.
Source: Official authority

The application should never present an unverified report as a confirmed fact.

⸻

🛡️ Trust & Verification

Trust is one of SafeSignal’s most important design principles.

Information should be categorized as:

🛡️ Official Government Source

Information directly from a relevant government authority.

✓ Verified News Source

Information from a reputable news organization reporting on a documented event.

⚠️ Unverified Report

Information that has not been sufficiently confirmed.

Unverified information should never be presented as an official warning.

⸻

📍 Evacuation Information

SafeSignal is designed to show evacuation information only when it can be verified.

Potential information includes:

* Evacuation zones
* Official shelters
* Shelter addresses
* Opening status
* Accessibility information
* Pet policies
* Distance
* Official source
* Last updated time

The application must never invent a shelter.

If verified information is unavailable, the correct response is:

No verified evacuation information is currently available.

📱 Mobile-First Design

Emergencies often happen when users are away from computers.

SafeSignal is therefore designed primarily for smartphones.

The interface uses:

* Large buttons
* Large text
* High contrast
* Clear icons
* Simple language
* Minimal animations
* Fast-loading layouts
* Responsive design
* Accessible controls

The most important information should be available within one or two interactions.

⸻

♿ Accessibility

SafeSignal aims to remain usable under stressful conditions.

Accessibility considerations include:

* Screen-reader-friendly structure
* Keyboard navigation
* Large touch targets
* High-contrast elements
* Text labels alongside colors
* Reduced unnecessary animation
* Clear headings
* Simple instructions

Emergency information should never depend solely on color.

⸻

💾 Offline Preparedness

Flooding can cause:

* Internet outages
* Power interruptions
* Mobile-network congestion

A production version of SafeSignal should cache essential information such as:

* Emergency numbers
* Basic flood-safety instructions
* Emergency contacts
* Previously viewed information
* Preparedness checklists

Cached information must clearly say:

OFFLINE INFORMATION — MAY NOT REFLECT CURRENT CONDITIONS

SafeSignal should never pretend outdated cached information is live.

⸻

🔐 Privacy

SafeSignal should minimize the personal information it collects.

The application should not require an exact home address.

Location can be handled using:

* Country
* City
* Province
* Approximate GPS location

If GPS is used, the application should request permission first.

Personal preferences such as household information and emergency checklists can be stored locally where possible.

⸻

🤖 AI Assistance

A future production version can include SafeSignal AI.

Users could ask questions such as:

“There is flooding near me. What should I do?”

“Is my area affected?”

“What should I put in my emergency bag?”

“Where is the nearest verified shelter?”

The AI should use current verified information rather than relying only on its training data.

Every emergency response should show:

Information checked: [timestamp]
Sources:
[Official source]
[Official source]

If the AI cannot verify something, it must say so.

⸻

🧠 AI Safety Rules

SafeSignal AI must:

1. Never invent emergency information.
2. Never invent evacuation centers.
3. Never invent emergency numbers.
4. Never claim an evacuation order exists without verification.
5. Never claim an area is safe without reliable evidence.
6. Show when information was checked.
7. Prefer official government sources.
8. Clearly distinguish verified facts from uncertain reports.
9. Never encourage dangerous behavior.
10. Never encourage people to enter disaster zones.
11. Never encourage panic buying.
12. Prioritize emergency services when someone is in immediate danger.
13. Say when information cannot be verified.
14. Never override an official evacuation order.
15. Keep emergency instructions short and actionable.

🔑 API Security

API keys must never be placed directly inside frontend JavaScript.

Bad:

const API_KEY = "secret-key";

Instead, production applications should use a backend server and environment variables.

Example:

Frontend
   ↓
SafeSignal API
   ↓
Verified emergency sources
   ↓
Validated data
   ↓
AI processing
   ↓
SafeSignal user

⸻

⚡ Performance

SafeSignal is designed for situations where internet connectivity may be poor.

The application should prioritize:

* Small assets
* Fast loading
* Minimal JavaScript
* Efficient API requests
* Cached essential data
* Lazy loading for maps
* Responsive layouts

Emergency information should load before non-essential features.

Call the appropriate emergency service and follow official instructions.
